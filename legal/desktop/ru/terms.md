## 3. Официальная установка и отсутствие portable-дистрибуции

Поддерживаемый публичный Windows installer — `FluxoraSetup.exe` из официального Fluxora release channel. Setup выполняет per-user установку, обычно в `%LOCALAPPDATA%\Programs\Fluxora`, без обязательного повышения прав. По умолчанию он может создать ярлык рабочего стола и зарегистрировать `moddingflow://` для текущего пользователя. Repair и удаление меняют регистрацию и ярлыки только после ownership checks.

Fluxora не распространяется как portable program folder или portable archive. Loose payload files, staging directories, build outputs, update packages, manifests, signatures и inventories не являются альтернативными installer-файлами для пользователя. Получайте приложение только из официального канала и не запускайте внутренние update data как программу.

## 4. Требование WebView2

Интерфейсу Fluxora в Windows нужен Microsoft Edge WebView2. Если подходящий runtime уже присутствует, Setup может установить Fluxora offline. При его отсутствии Setup до создания web-интерфейса объясняет зависимость и только после вашего подтверждения запускает встроенный официальный Microsoft Evergreen Bootstrapper. Bootstrapper требует online connection к Microsoft и регулируется условиями Microsoft. При отказе или отсутствии сети Setup не сможет продолжить, пока WebView2 не будет установлен другим поддерживаемым способом.

## 5. Транзакции установки, repair и recovery

Setup проверяет target path, free space, package integrity и ownership существующей установки. Нажимая «Установить» после принятия этих условий и ознакомления с Политикой конфиденциальности, вы разрешаете одну операцию: install, repair или update встроенного payload и последующее автоматическое доведение установки до последней более новой подписанной stable-версии, если она доступна. Установка из Setup изначально не имеет подписанной квитанции update inventory и поэтому для этого первого обновления после Setup использует только подписанный full package; downgrade и выбор delta запрещены. Setup и Updater используют staging, atomic commit, долговечную запись о принадлежности, recovery markers, health probation и rollback. Отмена возможна только до commit бесшовной передачи Updater. После этой границы закрытие и отмена блокируются до завершения или восстановления транзакции. При ошибке обнаружения или загрузки Setup запускает успешно установленную встроенную версию; при ошибке применения native workflow выполняет rollback и запускает безопасно восстановленную предыдущую версию.

Не изменяйте transaction, backup, watchdog, receipt или recovery files во время работы Setup/Updater. Потеря питания, ошибка накопителя, защитное ПО, недостаточные права или ручные изменения файлов всё равно могут помешать восстановлению.

## 6. Обновления

Fluxora проверяет закреплённые публичные GitHub Release assets при запуске, каждые 15 минут во время работы главного окна, при возврате фокуса в него после не менее пяти минут и по вашему запросу в настройках. Эти проверки только обнаруживают более новую подписанную версию; package download, installation, завершение и restart начинаются только после выбора действия обновления. В Setup действие «Установить» прямо включает автоматическую подписанную проверку после установки и, если доступна более новая версия, загрузку full package, передачу изолированному Updater, установку, health verification и restart.

Обновления могут быть подписанными full packages или delta для точно совпадающей предыдущей версии. Full package используется, если безопасная delta недоступна или у установки нет подходящей квитанции. До commit Fluxora проверяет signed manifest, package hash и target-file inventory. Updater ждёт завершения приложения, работает из изолированного runtime, выполняет staging изменений, запускает новую версию в probation, требует свежий health acknowledgement и затем выполняет finalize либо rollback.

Устанавливайте обновления безопасности и совместимости в разумный срок. В соответствии с § 327f BGB необходимые обновления, включая обновления безопасности, в применимых случаях должны предоставляться пользователю с соответствующим уведомлением. При выполнении установленных законом условий отказ от установки в разумный срок после надлежащего уведомления может повлиять на ответственность за дефект, вызванный исключительно отсутствием обновления. Обязательные права потребителей сохраняются.

Update infrastructure и сторонний hosting могут быть недоступны. Signature verification снижает supply-chain risk, но не заменяет operating-system code signing, backups и получение Fluxora только из официального канала. Текущие Windows executables и Setup намеренно распространяются без платного Authenticode-сертифика доверенного издателя, поэтому Windows может показать предупреждение о неизвестном издателе или репутации.

## 7. Обязанности пользователя

Перед установкой мода, deployment файлов, импортом manager data, изменением load order, запуском tool, обновлением или AI-assisted изменением:

- проверьте игру, профиль, paths, mod permissions, dependencies и предлагаемое действие;
- храните проверенные backups saves, projects, profiles, configuration и незаменимых archives;
- закройте или приостановите tools, которые могут блокировать те же файлы;
- изучите warnings, operation summaries и recovery instructions;
- соблюдайте правила игр, платформ, API, авторского права, лицензий и сообществ.

Защищённое дерево Fluxora `Downloads` и логи являются пользовательскими данными и исключены из замены application payload, но это не заменяет backups.

Fluxora не может гарантировать их данные, ссылки, identifiers, файлы или ответы.

Передача `moddingflow://` обозначает конкретный артефакт ModdingFlow. Fluxora проверяет метаданные артефакта, включая ожидаемый размер и SHA-256, и требует выбрать совместимую сборку и профиль, а затем явно подтвердить актуальный план установки, прежде чем необходимые загрузки будут поставлены в очередь менеджера. Изменённый или конфликтующий план блокируется и должен быть проверен повторно.

Downloads могут быть задержаны, отозваны, неполны, вредоносны или неверно описаны. Fluxora выполняет integrity/path checks, реализованные в текущей версии, но вы отвечаете за выбранный контент, permissions и итоговое состояние игры.

## 9. AI и локальный голосовой ввод

AI output может быть ошибочным, неполным, устаревшим или небезопасным. Публичный web content, model output и полученные файлы являются недоверенными входными данными. Native policy checks, typed capabilities, confirmation requirements, transaction limits и rollback снижают риск, но не делают output авторитетным. Проверяйте diffs и результаты.

Распознавание речи выполняется локально встроенными моделями. Только отправленный вами транскрипт входит в AI request flow. Проверьте его до отправки, особенно если он может стать основой предлагаемого действия.

Не отправляйте secrets, незаконный контент или ненужные персональные/конфиденциальные данные. Вы должны иметь право обрабатывать и передавать предоставленный сторонний контент.
